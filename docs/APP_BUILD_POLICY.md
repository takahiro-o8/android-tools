# 全Androidアプリ共通の開発・ビルド方針（2026-11-16）

**唯一の正本**：この文書と[AGENTS.md](../AGENTS.md)、[署名・配布の安全基準](RELEASE_SAFETY.md)。新旧の文書が食い違う場合、ユーザーの最新指示と本書が優先する。Codex・Claude・Cursor・Meta Muse Code・Grok Build・将来のAIのいずれにも適用。AI専用の別リポジトリは不要。

## 個人用アプリの即時本番運用
- 開発は一人で行い、別AIが同じアプリを同時改修しない。AIに依頼した変更が反映されたら**直ちに最新版を本番として使う**。PR、承認、単体テスト・lintの常時実行は必要ない。E2E・エミュレーターの自動/手動テストは実行しない。
- mainへのPushで、ビルド成功後に既存固定鍵で正式APKを署名・検証し、GitHub Releasesへ正式版として公開することを目標とする。旧コードのビルド実装がまだこの方針に未移行なら、移行が必要である。
- 失敗したビルドは公開しない。先行ビルドの競合を避け、古いAPKが最新を上書きしないようにする。
- 最新正式APK＋過去2件の計3件だけを残す。版名を変えずに新しいビルドを公開する場合は各公開APKを別の更新版として扱う。古い正式Release・APK・対応タグは削除する。
- 開発版`dev`、診断用`ci-logs`/`e2e-report`、下書きReleaseは今後作成せず、旧分も削除する。診断にはGitHub Actionsの実行ログを利用する。Gitコミットのソース履歴は残す。

## Kotlinと最新版ツールチェーン
- Androidの自作アプリ本体、自作ヘルパー、自作テストを完全Kotlin化。残存自作`.java`は次回そのアプリを改修する際に**Kotlinへ移行して削除**。ラッパーだけをKotlinで書いてJavaを残さない。外部ライブラリや自動生成コードは対象外。
- GradleはKotlin DSLを使用。SDKの`compileSdk`/`targetSdk`、Android Gradle Plugin、Gradle、Kotlin、JDK、依存ライブラリを、**正式安定版かつ組み合わせ互換性のある最新構成**にアプリ間で統一する。alpha/beta/RCを無理に採用しない。
- `minSdk`はPixel 8の発売時OSであるAndroid 14（API 34）を標準下限とする。最新版SDKに合わせて無条件に高くしない。現行Pixel 8が実際に起動することを優先する。
- バージョン変更による権限・通知・バックグラウンド処理の互換性は修正し、ビルド・署名検証成功をもって移行完了とする。書類の更新だけでは移行完了とみなさない。
- アプリID、既存の固定署名鍵、ユーザーデータと更新互換性、アプリ固有の権限・機能は保持する。

## 指示MDとREADMEの統一
- `android-tools/AGENTS.md`と本書を全AI共通の正本とする。各アプリの`AGENTS.md`/`CLAUDE.md`は短い参照と固有事項だけにする。
- AIが別リポジトリの文書を自動で読める保証はない。作業開始時に実際の取得を確認する。取得できないなら適用済みと断言しない。
- READMEは目的、使い方、正式APKのインストール/更新、固有の権限・制約、共通ルールへの参照を基本構成とする。
- [Material Design 3共通仕様](MATERIAL_DESIGN.md)・[ウィジェット仕様](WIDGET_STYLE.md)・[安全な署名・配布](RELEASE_SAFETY.md)を適用する。
- README・古いADRに書かれた旧版の検査/配布条件は当時の履歴として尊重するが、現行運用の根拠にしない。

## 実装の状況（2026-11-16時点）
- 5アプリの主要ワークフローは共通の`actions/build`へ切り替え済み。単体テスト・lintを通常のAPK公開条件にせず、E2Eを完全廃止し、正式APKだけを配布する。各アプリの旧ワークフローは撤去済み。
- Kotlin自作Javaの残存は`limitless`の補助ソースを変換して解消済み。全アプリのSDK・AGP・Gradle・JDK・minSdkも共通設定に変更済み。ただし**実際の成功ビルドを確認したアプリと、署名鍵不足などにより配布できていないアプリを区別**する。
- `file`はユーザーが再インストールを承諾し、新しい固定署名鍵を作成して正式APK `File-1.4.0.b8.apk`（build-8）を公開済み。以後その鍵を使用する。
- `scripts/retain-apk-versions.py`は最新3正式APKと補助Releaseの削除に使用。診断用のGitHub Actions実行ログは残す。
- Markdownだけが後続コミットされた場合は、差分を確認してコードに変化がなければ先行する成功APKの配布を許可する。コードやビルド設定に新しい変更があれば古いAPKを公開しない。

## 署名鍵の管理（2026-11-16 最新の最終方針）
- **各既存アプリの署名鍵は変更しない。** アプリ間で同じ秘密鍵に統一する案は撤回した。LauncherはLauncherの固定鍵を使い、他の各アプリもそれぞれの固定鍵を維持する。
- GitHub Freeの個人アカウントで各アプリを独立した非公開リポジトリとして運用する限り、秘密鍵を1種類にしても各リポジトリのSecrets登録が不要にはならない。鍵の統一では登録作業が減らず、既存設定・データが消える再インストールが発生するため採用しない。
- **共通化の対象は**鍵の検証、既存鍵からの署名、APKの検証、versionCode、正式Releaseへの配布、自動整理という**手順・スクリプトのみ**。Secretの値と別アプリの証明書は共通化しない。
- 新しいアプリでは、固有のアプリIDと固定鍵を作り、そのリポジトリのSecretsへ初回のみ登録する。アプリのバージョン更新のたびにSecretsを再登録しない。
- 既存鍵が使えない場合は公開を一度停止し、ユーザーに旧版の再インストールとデータ消失を案内する。ユーザーが再インストールを許容する最新方針でも、鍵の再生成は都度明示的な指示を受けてから行う。

## 新規アプリの初回鍵管理方式（2026-11-16追記）
- **新規アプリは、GitHub Freeの個人用非公開リポジトリで`scripts/bootstrap-signing.sh`を使う。** アプリ固有のランダム32文字以上のパスワードをSecretに1項目だけ登録し、初回にパスワード保護PKCS12と証明書指紋をGitへ固定する。以降のビルドでは同じ鍵を使う。初回作成の明示操作がなければ生成しない。
- `file`は既存鍵の紛失・アンインストール許可という特別な事情から新方式へ移行する。**他の既存4アプリの鍵は絶対に変更しない。**
- この方式は暗号化鍵ファイルをGit履歴に保管するため、漏洩時のパスワード総当たり攻撃リスクがある。非公開リポジトリと独立した強いパスワードが必要。復旧バックアップはユーザーの方針により作成しない。

## GitHub Actions計算リソースの削減（2026-11-16 最終指示）
- **E2Eを完全廃止**：全アプリ・共通基盤からE2EのAction、テスト、手順、補助APK、エミュレーター起動スクリプトを撤去。今後は依頼の有無に関わらずE2Eを実装・実行しない（方針変更の明示指示がある場合を除く）。
- mainへのアプリ本体・ビルド設定変更でのみ、署名済み正式APKを1件作成。Markdown・仕様文書・E2E除去のみのPushでビルドしない。新規アプリの通常チェックは署名済み本番APKのビルドと証明書・アプリID・versionCode確認に限定。
- 署名鍵・パスワードをユーザーが別途バックアップすることは必須としない。GitHubの鍵とSecretを失った場合はアプリの再インストールを許容し、新しい鍵に切り替える。ただし再生成前に**旧アプリの設定・アプリ専用データが失われること**を明示する。
- GitHub Actionsで通常どおり同じ鍵を使った継続更新を維持し、鍵の再生成を毎回行わない。鍵のバックアップ用Actionsや復旧用テキストファイルは作らない。

## 署名鍵のバックアップ省略・確定（2026-11-16）
- 既存の5アプリは**鍵を紛失したときの再インストールをすべて許容**。バックアップ・個別パスワード管理・PCの復旧秘密鍵管理を必須にしない。新しい鍵の作成は本当に紛失したときだけ、ユーザーの明示的な許可とともに行う。
- GitHub Secretsと非公開Gitにある現在の鍵はそのまま残し、普段のAPKは同じ証明書で署名し続ける。鍵を失った場合、古いアプリを上書きできずアプリ専用データが消える点を案内する。
- 既存のGitHub Secretsの値はGitHub APIから取得不可。ユーザーが明示的に希望し、値が取得可能なら平文テキストファイルの生成は可能だが、既存Secretの値を推測しない。
