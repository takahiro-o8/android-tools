# 全Androidアプリ共通の開発・ビルド方針（2026-11-16）
この文書は既存/新規アプリすべてについて、以前の共通開発手順と相反する場合に優先する。アプリ固有の機能仕様・アプリID・既存固定署名鍵・データ互換性は保持する。開発担当AIがClaude/Codex/Cursorのどれでも同一方針を適用する。

## 個人用の継続的本番運用
- 一人で自分だけが使うアプリであり、同一アプリを複数AIが同時改修しない。AIへの変更指示が実装されたら最新版をすぐ日常使用する。レビュー承認やPRは必須にしない。
- 原則、mainへの変更でAPKをビルドし、**ビルド成功、既存の固定鍵による署名、署名証明書の検証、更新可能な増分versionCode**を満たしたものをGitHub Releasesに最新版として公開。テスト・lint・E2Eはビルドの常時前提条件にしない。問題解析や必要時に個別実行する。
- 開発途中の古いビルドはキャンセルできるが、署名済みAPKの最終公開処理は競合しないよう直列化し、古いコミットのAPKで新しい公開を上書きしない。失敗したビルドは公開せず、直前に成功したAPKを残す。
- APKはZIPではなく実ファイルをReleasesに保存。案内はReleaseページを基本とする。秘密鍵・秘密情報・個人データをリポジトリやログに残さない。

## Kotlinへの完全統一：次の改修時に必須
- **アプリ本体・自作テスト・自作ヘルパーのソースにJava（.java）が1ファイルでも残っていたら、そのアプリを次に改修する際にすべてKotlinへ変換し、元の自作Javaファイルを削除する。** Kotlinでの部分ラッピングのみでJavaを残してはいけない。移行が未完了なら完了扱いにしない。
- GradleのスクリプトはKotlin DSL（.gradle.kts）へ統一。生成コード、外部ライブラリの内部実装、JDK自体のJava実装は書き換え対象外。
- 現在の確認：limitlessのtools/widget-host-check/src/main/java/com/aiusage/hostcheck/HostActivity.javaが自作Javaの残存箇所。他の4アプリの現行mainには自作.javaなし（2026-11-16時点）。
- アプリID、既存の固定署名鍵、設定・データ保存形式などの更新互換性を維持する。

## 最新の安定版ツールチェーンへ全アプリ強制統一
- 既存・新規すべてで、原則**最新の正式安定版**を採用する。EAP/alpha/beta/RCは正式版より新しくても採用しない。
- Android SDK compileSdk/targetSdk、AGP、Gradle Wrapper、Kotlin、JDK、依存ライブラリ、SDK Build Toolsはプロジェクト間で同じ**最新かつ組み合わせとして動作可能な**安定版へ移行する。旧版に留まることを既定の例外としない。個別アプリの次の改修では必ず同期を確認・実行する。
- 2026-11-16時点の参考値（これは固定の上限ではなく次回作業時に公式情報を再確認）：Android API 37、AGP 9.5.1、Gradle 9.9.1、Kotlin単体の最新安定版 2.4.21。**これらを無検証で同時指定してよいという意味ではない。** Kotlin Gradleプラグインの公式互換表はKotlin 2.4.21をAGP 9.3.1/Gradle 9.7までフルサポートとしており、AGP 9.5以降では組み込みKotlinへ移行するなど相互互換性を解決する。ビルド成功の実証なしに移行完了と報告しない。
- JDKは「最大数字」を無条件採用しない。AGP・Gradleでサポートされる**最新の動作可能な安定版JDK**に統一し、実行JDKとソースのJVMターゲットの違いを区別する。
- **minSdkは例外的に最新APIに合わせない。Pixel 8が発売時対応していたAndroid 14（API 34）を基本の下限**とし、実際に使用するPixel 8のOSで起動することを優先する。minSdkを37へ一律引き上げるとAndroid 17未満の端末ではPixel 8であっても動作しない。
- targetSdkを37にすると権限やバックグラウンド動作等の挙動が変わる。互換修正・最低限の起動確認をしてから最新版APKを公開し、修正不能なら公開を止めて問題を明示する。旧版への恒常的な据え置きを黙認しない。
- アプリ固有の機能に必要なライブラリやAndroid機能の差分は残す。全アプリで同一バージョンにできる部分は最新の安定版に揃えるが、無意味に依存ライブラリを追加しない。

## MD・READMEを極力共通化
- この文書と共通AGENTS.mdを正本として、各リポジトリのAGENTS.md/CLAUDE.md/Cursor向け指示は短い参照とアプリ固有事項だけにする。**AIが外部リポジトリを自動取得できない環境では、作業開始時に共通ルールを明示的に取得してから作業する。取得できないならその旨を報告し、適用済みと断言しない。**
- READMEは「何のアプリか」「使い方」「Releasesからのインストール」「開発/ビルド（共通方針へのリンク）」「アプリ固有の制約」を基本構成とし、共通説明の重複記述は減らす。履歴文書や固有仕様は無理に消去しない。
- 変更はアプリ本体と対応する指示ファイルの整合を保って進める。「最新に統一」と書いたことだけで実際のGradle/SDK/ソースが移行済みになったと扱わない。


## 過去の配布版の自動整理（2026-11-16追加）
- すべてのアプリで**最新版の正式APKと、それに先行する過去2バージョン**、合計**3つの異なる正式バージョン**のみをGitHub Releasesに残す。4世代目以前の正式ReleaseとAPKアセット、対応するリリースタグは削除する。
- 削除は正式リリースが成功した後に実行し、失敗中・作成途中・APKのない下書きは配布済みとして数えない。個々のリリース内で同じバージョンが重複した場合は最も新しい配布だけ保持する。過去のバージョン順は数値的なバージョン順（例：3.10.0は3.9.0より新しい）で判断する。
- Gitのコミット履歴、ブランチ、ソースファイル、Signing Secrets、端末のユーザーデータは削除しない。アプリ本体ではないdev/ci-logs/e2e-report等の診断用Releaseと下書きは別扱い。従来の「5世代保存」「配布版を削除しない」などの競合する記載より本規定を優先する。
- 共通スクリプト scripts/retain-apk-versions.py を使い、各アプリのGitHub Actionsで新しい正式配布完了後に実行する。署名済みの最新APKが消えないよう、**最低3つの識別できる正式版が存在しない場合は削除しない**。まず計画を表示し、実行時は対象バージョンをログに記録する。

## 2026-11-16追加：正式版のみ配布する最新運用
- `dev`、診断用`ci-logs`や`e2e-report`、下書きReleaseは作成しない。既存のものも削除する。ビルド失敗の調査はGitHub Actionsの実行ログによる。
- mainに反映した変更は、ビルド成功・固定署名・versionCodeの更新確認後、そのまま本番APKとして正式Releaseを公開する。最新と過去2件（計3件）の配布APKのみ保持する。
- 同じversionNameでも変更ごとに増えるversionCodeと実行番号を使って別の更新版として扱う。保存数の判断は正式APKが公開された時系列による。
- `scripts/retain-apk-versions.py --keep 3 --apply --remove-aux`で正式版以外も削除する。
- 古い`actions/build`はdev/診断Releaseを作成するため、新たな共通公開処理に置換するまで使用を停止する。

## 開発AIを限定しない共通ルール（2026-11-16追記）

- 開発担当は **Codex、Claude、Cursor、Meta Muse Code、xAI Grok Build、および将来のAI** のいずれでもよい。AIの製品名が変わっても同じAndroidビルド・署名・配布・Kotlin・SDK・MD方針を適用する。
- **AIごとの管理リポジトリを新設しない。** 共通方針の唯一の正本は `android-tools/AGENTS.md` と `android-tools/docs/APP_BUILD_POLICY.md`。各アプリの `AGENTS.md` を入口とし、Claude向け `CLAUDE.md` は短く共通ルールを参照する。READMEは人向け説明を残す。
- Meta Muse Code・Grok Buildとも `AGENTS.md` のプロジェクトルールを読む機能がある。ただしリポジトリを信頼済みとする操作など製品固有条件があり、外部URLは勝手に読み込まれるとは限らないため、作業開始時に共通ファイルの実際の取得を指示する。
- `codex` リポジトリは旧・開発指示資料の保管場所であって、今後の独立した正本ではない。必要な履歴は保持し、参照先は `android-tools` に統一する。
