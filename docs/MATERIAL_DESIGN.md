# Androidアプリ共通：Material Design

恒常的なオーナー指示。既存のFile・その他アプリ・今後新規に開発するアプリのすべてに適用する。新規実装と画面改修では常に最新安定版Material Designを採用する。現在の基準はMaterial 3。

- 公式Materialコンポーネントを使う。ViewsならMaterial ComponentsのTheme.Material3.DayNight、Composeならandroidx.compose.material3。プラットフォームのTheme.Materialを代用しない。
- colorSurface／colorOnSurface／colorPrimary／colorSecondaryContainer等のテーマトークンを使い、ハードコードした昼夜パレットで模倣しない。対応端末ではDynamic Colorを使用。ライト・ダーク両方を確認する。
- 公式のボタン、検索欄、チェックボックス、メニュー、ダイアログ、進捗、スライダー等を使用し、文字サイズ・角丸・余白・状態表示を統一する。小型端末・画面回転・文字拡大でも操作できる配置とする。
- 操作領域は原則48dp以上。アイコンのみの操作には読み上げ名を付ける。選択・フォーカス・押下・無効・エラーを識別できるようにし、色だけに依存しない。
- ライトは白ベース、ダークは黒ベース。2〜5段階程度の選択は1行のセグメントボタンで示す。連続値の再生位置などはスライダーを使用する。
- Google Sans優先、未搭載端末は標準フォント。ウィジェットにはWIDGET_STYLE.mdの透明背景・ライト／ダーク文字色の仕様を適用する。
- 全画面・内蔵ビューアー・初回権限案内・エラー・処理中画面も対象。共通コードに整理し、同じ機能の見た目を画面ごとに独自実装しない。
- 実装・テストはKotlin、Gradle Kotlin DSL。既存データ・アプリID・固定署名を維持。代表画面の端末E2Eとスクリーンショットを残す。

この方針を各アプリのAGENTS.md／CLAUDE.mdと新規アプリの雛形から参照する。既存アプリはそのアプリを改修するときに適用し、他のアプリを無関係な作業で一括変更しない。
